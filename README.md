## 1. Project Overview & Context

In Kenya, agriculture employs over 70% of the rural workforce, largely on rain-fed smallholder plots measuring less than 2 hectares. Climate change and regional atmospheric cycles (ENSO and Indian Ocean Dipole) have destabilized traditional bimodal rainfall calendars (Long Rains: March–May; Short Rains: October–December).

Existing weather forecasts from the Kenya Meteorological Department (KMD) operate at broad county/macro-scales (10–50 km grids). These macro forecasts fail to capture the intense sub-kilometer micro-climates generated by Kenya’s varied topography (e.g., the Great Rift Valley, Mount Kenya, Aberdares, and western lake basins). Deploying dense physical IoT sensor hardware across smallholder farms is economically prohibitive.

**This platform computationally downscales regional meteorological data into hyper-local, sub-kilometer weather forecasts and actionable agronomic risk advisories using a hybrid machine learning architecture.**

## 2. Core Architecture & Hybrid Machine Learning Methodology

### 2.1 The Two-Stage Hybrid Architecture
1. **Long Short-Term Memory (LSTM) Recurrent Neural Network:**
   - Analyzes multi-day chronological weather sequences (past 14 days / 336 hours).
   - Preserves cell states to capture seasonal autocorrelation, diurnal solar curves, and bimodal tropical rainy periods.
   - Generates a baseline continuous atmospheric prediction: $\hat{y}_{\text{LSTM}}$.
2. **Extreme Gradient Boosting (XGBoost) Regressor:**
   - Ingests high-dimensional tabular features: localized terrain elevation ($z$), slope, adiabatic lapse-rate offsets, cyclic sin/cos calendar transforms, and multi-step lag variables ($t-1, t-2, t-24, t-48$).
   - Learns and predicts the residual error correction: $\hat{e}_{\text{XGB}} = y - \hat{y}_{\text{LSTM}}$.
3. **Composite Downscaled Prediction:**
   $$\hat{y}_{\text{Final}} = \hat{y}_{\text{LSTM}} + \hat{e}_{\text{XGB}}$$

### 2.2 Time-Series Walk-Forward (Rolling Origin) Validation
To strictly eliminate look-ahead data leakage, model performance is validated sequentially along a chronological axis across 3 folds (expanding windows), benchmarking:
- **Naive Persistence Baseline** ($y_{t+h} = y_t$)
- **Historical Rolling Average** (24-hour moving window)
- **Standalone XGBoost**
- **Standalone LSTM**
- **Hybrid Stacking Architecture**

Metrics tracked: **Root Mean Squared Error (RMSE)**, **Mean Absolute Error (MAE)**, and **Coefficient of Determination ($R^2$)**.

## 3. Agronomic Risk Rules Engine

Continuous meteorological predictions are dynamically evaluated against crop physiological thresholds (e.g., Highland White Maize, Rosecoco Beans, Shangi Potatoes, Sorghum, Tea) to prevent severe agricultural failure modes:
- **Fertilizer Washout Risk:** Detects upcoming convective downpours ($\ge 20\text{ mm}$ in 48h) to alert farmers against top-dressing fertilizers.
- **Seed Desiccation Warning:** Detects high thermal spikes ($\ge 29.5^\circ\text{C}$) coupled with zero rainfall on recién-sown topsoil.
- **Fungal Blight & Stripe Rust Alert:** Detects prolonged relative humidity ($\ge 80\%$ for $\ge 20$ hours) within optimal fungal temperature ranges.
- **Optimal Spraying Windows:** Recommends calm wind periods ($< 3.5\text{ m/s}$) with zero rainfall for foliar nutrient and pest control applications.

## 5. Quick Start & Execution Guide

### Prerequisites
- Python 3.11+ (or Python 3.13)
- Git
- (Optional) Docker & Docker Compose for PostgreSQL + TimescaleDB container

### 1. Clone & Set Up Virtual Environment
```bash
git clone <repository_url>
cd "hyper-local weather"

# Create virtual environment
python -m venv .venv

# Activate virtual environment (Windows PowerShell)
.\.venv\Scripts\Activate.ps1
# (Linux / macOS)
# source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt
```

### 2. Configure Environment Variables
Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```
*(By default, `USE_SQLITE=True` enables instant local zero-dependency testing. Set `USE_SQLITE=False` when running PostgreSQL/Docker).*

### 3. Initialize Database & Seed Demo Data
```bash
python manage.py makemigrations accounts farms climate forecasting advisories
python manage.py migrate
python manage.py seed_data
```
The `seed_data` command populates:
- Staple Kenyan crop profiles (Maize, Beans, Potatoes, Sorghum, Tea)
- Regional meteorological stations (Nakuru, Kericho, Eldoret, Embu)
- Demo accounts:
  - **Farmer:** `kitto_farmer` / `FarmerPass123!` (or phone `0712345678`)
  - **Admin:** `admin` / `AdminPass123!`
- Sample registered farm plots with coordinates and elevation in Nakuru.

### 4. Run Automated Test Suite
```bash
python manage.py test tests
```
Executes all unit, GIS polygon centroid, rules engine, and ML walk-forward tests.

### 5. Train / Benchmark Machine Learning Models
```bash
python -m ml_engine.training_pipeline
```
Executes walk-forward backtesting across all architectures and serializes trained production weights to `ml_engine/weights/`.

### 6. Start the Development Server
```bash
python manage.py runserver
```

- **Register New Farm Plot:** [http://127.0.0.1:8000/farms/register/](http://127.0.0.1:8000/farms/register/)
- **Admin ML Operations Panel:** [http://127.0.0.1:8000/admin-panel/ml/](http://127.0.0.1:8000/admin-panel/ml/)
- **Django Administration:** [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/)
